# Bundle Update Log

## 2026-10-25
* **Update**: Added an **Event check-in** kiosk tab (`/event-check-in`) mirroring the check-in page but with an events dropdown instead of trainings; it toggles event participants via a shared `ParticipantComponents.selectable_card/1`. Documented in [Events](/architecture/events.md) and [Web layer](/architecture/web-layer.md).
* **Update**: Added an **Events** tab: one-off, single-day events (name, date, optional times) with their own participant list, managed under `/events` (`EventLive.Index/Form/Show`). The event page is a check-in-style picker that toggles participants, stored in the new `event_participants` join table. Documented in [Events](/architecture/events.md), [Domain model](/architecture/domain-model.md), and [Web layer](/architecture/web-layer.md).
* **Update**: Members/participants are now sorted by first name (the training members page, the check-in kiosk, and the participants listing).
* **Update**: The check-in kiosk now defaults to the selected training's **members** (`training_members`) instead of its attendance-derived "regulars"; the **Show all** toggle still lists everyone regardless of training. Documented in [Web layer](/architecture/web-layer.md) and [Elixir/Phoenix idioms](/architecture/idioms.md).
* **Update**: Checking a participant into a session now also adds them to that training's member list (`training_members`) if they aren't a member yet — add-only, never removing. Documented in [End-to-end flows](/architecture/flows.md).
* **Update**: The user-management import now records which trainings each member participates in (a new `training_members` join table between participants and trainings), and a training detail page (`/training/:id`, via the **Members** action on the training list) lists those members. Added `Tracker.list_training_members/1` and `add_training_member/2`. Documented in [Imports](/architecture/imports.md), [Domain model](/architecture/domain-model.md), and [Web layer](/architecture/web-layer.md).
* **Update**: The user-management import now imports every member instead of only those enrolled in a training that already existed. Members whose configurable exit field (`Austritt`) is non-empty are skipped, and any training a member is enrolled in that doesn't exist yet is created with a default schedule (Monday 19:00–21:30). The Webling connector gained an `exit_field` config, returns each member's trainings, and the source behaviour's `fetch_members/1` no longer takes training aliases. Documented in [Imports](/architecture/imports.md) and [Web layer](/architecture/web-layer.md).
* **Update**: Added a version banner to the admin page showing the app version and git revision (`AttendanceTracker.Version`). The revision is baked into the release from the `GIT_SHA` build arg (passed by the publish workflow), falling back to the local git revision or `"unknown"`. Documented in [Web layer](/architecture/web-layer.md) and [Deployment](/deployment.md).

## 2026-10-13
* **Fix**: The kiosk session PIN could be bypassed by LiveView live navigation (e.g. the navbar "Check-in" link from `/start`), which reuses the WebSocket and skips plugs. Added a `KioskSessionHook` `on_mount` guard and a dedicated `:kiosk` `live_session`, and the plug now mirrors the kiosk token into the Plug session. Documented in [Web layer](/architecture/web-layer.md).
* **Update**: The check-in kiosk now defaults to showing only a selected training's "regulars" (participants who have ever attended it), with a no-admin **Show all** toggle to reveal everyone. The admin participant listing gained a **Trainings** column, and the participant detail page a trainings table, showing which trainings each participant has attended. Documented in [Web layer](/architecture/web-layer.md) and [Elixir/Phoenix idioms](/architecture/idioms.md).
