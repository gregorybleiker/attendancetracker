# Bundle Update Log

## 2026-11-09
* **Feature** (0.7.0): Brute-force throttling for the PIN gates. A new `AttendanceTracker.RateLimit` GenServer keeps a per-key sliding window of failed attempts, and `AttendanceTracker.PinThrottle` applies the policy (5/10 failures per client IP in five minutes for the admin/session PINs, plus a higher aggregate cap against distributed attacks). All four verification points — `SessionController` create/start (HTTP) and the `AdminLive` unlock and `CheckInLive` check-out prompts (LiveView events) — now check the throttle first, count failures, clear the per-IP counter on success, and show a "too many attempts" error when over the limit. The client IP comes from `AttendanceTrackerWeb.ClientIP` (rightmost `x-forwarded-for`, captured in `mount/3` for LiveViews). The shared nginx stack got a coarse per-IP `limit_req` on `/login` and `/start` as an edge backstop. Documented in [Web layer](/architecture/web-layer.md).

* **Update**: The info slides editor is an admin-mode item in the left flyout menu (`/admin/infos`), alongside the other admin links. Documented in [Info screen](/architecture/info-screen.md).
* **Feature**: Idle **info screen**. When a kiosk screen is untouched for a configurable time (`idle_timeout_minutes`, default 10) it switches to a full-screen slideshow of admin-authored slides that rotate every `info_rotation_seconds` (default 15); tapping the screen returns to check-in. Slides (`infos` table, `Tracker.Info`) are managed at `/admin/infos` with a contenteditable **WYSIWYG editor** (colocated `.WysiwygEditor` hook). Idle detection and rotation use a colocated `.InfoMode` hook on `CheckInLive`/`EventCheckInLive`. Documented in the new [Info screen](/architecture/info-screen.md) concept, plus [Domain model](/architecture/domain-model.md), [Web layer](/architecture/web-layer.md), and [Directory map](/architecture/directory-map.md).

* **Update**: The kiosk's **Training** dropdown now only lists trainings that run on the selected **date**'s weekday (each training's weekday is configurable in the training form). Changing the date filters the options and keeps the current pick only if it still matches, otherwise falling back to the first matching training or an ad-hoc session. Documented in [Web layer](/architecture/web-layer.md) and [End-to-end flows](/architecture/flows.md).
* **Update**: Aligned the app header with the page body: both now use the same centered `mx-auto max-w-5xl` container (the header was `max-w-7xl`), so their left/right edges line up. Documented in [Web layer](/architecture/web-layer.md).
* **Update**: Removed the kiosk's "Tap your photo to check in" heading and date subtitle, and moved the **Show all** toggle and the **present** count pill into the app header alongside the date/training selectors, so the body is only the participant grid. Documented in [Web layer](/architecture/web-layer.md).
* **Update**: Moved the check-in kiosk's **date** and **training** selectors out of the page body and into the app header, via a new optional `<:header>` slot on `<Layouts.app>`. Frees vertical space for the participant grid. Documented in [Web layer](/architecture/web-layer.md) and [End-to-end flows](/architecture/flows.md).
* **Update**: Shrank the participant tiles so a 1920×1200 kiosk shows 20 at once (4 rows × 5 columns): the kiosk and event-picker avatars are capped at `size-16 sm:size-20`, tile padding/gaps tightened (`p-3`, `gap-1.5`), and the grid gap reduced to `gap-3`. The participant detail page keeps its larger avatar. Documented in [Web layer](/architecture/web-layer.md).
* **Update**: Replaced the horizontal navbar (and the separate mobile dropdown) with a single off-canvas **left flyout** menu shared by every breakpoint, opened by a hamburger button in the header. All items — Check-in, Event check-in, the admin links, language, and theme — live in the drawer, which toggles via LiveView `JS` commands and Tailwind `data-[open=true]`/`group-data-[open=true]` variants. Documented in [Web layer](/architecture/web-layer.md).
* **Update**: Admin login sessions now expire after an idle timeout that is configurable on the admin page (`admin_timeout_minutes`, default 10 minutes, validated to 1–1440). A successful login mints a token tracked in memory by the new `AttendanceTracker.AdminSession` GenServer; `Plugs.RequireAdminPin` refreshes it on every request and the new `AttendanceTrackerWeb.AdminSessionHook` `on_mount` hook refreshes it on LiveView mounts, events, and live navigation, redirecting an idle client to `/login`. The vestigial `:admin_pin_ok` session flag was replaced by `:admin_token`. Documented in [Web layer](/architecture/web-layer.md), [End-to-end flows](/architecture/flows.md), and [Domain model](/architecture/domain-model.md).
